Export format: Import Assistant v9 accepts readable full-project .L5K and .L5X exports. L5X must contain a full Controller element; component-only L5X is not treated as a complete project. Source-visible RLL rung text, declarations, task scheduling, produced/consumed metadata, MESSAGE configuration, modules, UDTs, and AOI declarations can be normalized into the existing analyzer model. Non-RLL routine content and source-protected or missing rung text are reported as unsupported rather than interpreted. .ACD remains a binary project format and must be exported to readable L5K or L5X first. Do not rename an ACD or unrelated XML file to bypass these source checks.

2. CONTROLLER IDENTITY

Describe this source without assuming site naming

Select an L5K or L5X export. Reference mapping is optional; source status is required.

If this controller matches a known ServoForge reference set, you can map it for comparison. Otherwise leave it site-specific and use the optional site, machine, and controller-purpose fields. ServoForge does not infer a universal machine identity from the file name or embedded controller name.

Boundary: Controller intake metadata is operator-supplied context. It is carried into every review candidate and exported review package, but it does not prove that the source is the current running program unless that status has been independently confirmed. An unmatched PLC target is a review candidate, not proof that ServoForge is missing a diagnostic. Dependency traces, interlock/permissive paths, recovery paths, and AFI locations are static source evidence; they do not prove live gate state, complete Boolean branch semantics, reset safety, AFI causality, alarm identity, or physical device condition. L5X normalization does not elevate site-specific tags, addresses, revisions, task settings, communication paths, timers, or reset structures into universal troubleshooting rules.
